# Студенту: от fork до сдачи

## Один раз в начале семестра

1. Создайте аккаунт GitHub, установите Git и Python 3.11 или новее.
2. Откройте преподавательский репозиторий курса, нажмите Fork. Оставьте ветку main.
3. В своём fork нажмите Code → HTTPS, скопируйте адрес. Подставьте его вместо YOUR_FORK_URL:

```bash
git clone YOUR_FORK_URL cs-practice
cd cs-practice
cd fiit
git remote -v
```

origin должен указывать на вашу копию. Не выполняйте git init внутри клонированного репозитория.

Задайте автора коммитов; замените значения на свои:

```bash
git config user.name "Имя Фамилия"
git config user.email "student@example.com"
python --version
```

Если в системе Python 3 запускается через python3 или py, используйте эту команду вместо python во всех примерах. Вход в GitHub и подпись автора коммитов — разные настройки. Не сохраняйте токены в файлах проекта.

## Каждая практика

Читайте labNN/README.md. Работайте только с опубликованными практиками. Сначала редактируйте и сохраняйте файл в редакторе, затем запускайте команды в терминале.

Для первой работы из папки направления:

```bash
python lab01/main.py
python tools/check.py lab01
git status
git add lab01/main.py lab01/REPORT.md
git diff --staged
git commit -m "Complete practice 01"
git push origin main
git rev-parse HEAD
```

main.py сначала ждёт ввода: введите числа из условия по одному на строку. Тесты передают данные сами. Последняя команда выводит полный SHA для сдачи. Проверяйте отправленную версию, а не несохранённые правки редактора.

## Когда преподаватель обновляет задания

В браузере откройте свой fork → Sync fork → Update branch. Затем при чистой рабочей папке выполните:

```bash
git pull --ff-only
```

Если обнаружено расхождение или конфликт, остановитесь и обратитесь к преподавателю. Не применяйте force push или команды удаления изменений. Синхронизация сохраняет опубликованные преподавателем задания, но конфликтующие правки требуют разбора.

Официальная инструкция: https://docs.github.com/en/pull-requests/how-tos/work-with-forks/syncing-a-fork
