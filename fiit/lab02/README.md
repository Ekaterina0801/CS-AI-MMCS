# ФИИТ · Практика 02 · Git и GitHub

**Статус:** опубликована · **Проверка:** история Git и защита · **Версия:** 1.0.0

## Цель

Создать репозиторий, выполнить status, add, commit, связать его с GitHub и отправить первое изменение. (2 пары)

## До начала

У вас есть fork этого репозитория, локальная копия и решённая lab01. Если Git не установлен, используйте инструкцию [начала работы](../docs/STUDENT.md). Команды ниже выполняются из папки направления. Унаследованные коммиты преподавателя не считаются вашими изменениями.

## Задание

1. Выполните `git status` и `git log --oneline -5`. Проверьте `git remote -v`: origin должен вести в ваш fork.
2. Создайте `lab02/NOTES.md`. Опишите своими словами рабочую папку, индекс и коммит. Сохраните, изучите status, подготовьте и создайте первый собственный коммит.
3. Дополните NOTES.md различием Git и GitHub. Перед add изучите `git diff`; после add — `git diff --staged`. Создайте второй собственный коммит.
4. Заполните `lab02/REPORT.md`, сохраните его третьим собственным коммитом и выполните push.
5. Откройте свой fork в браузере и убедитесь, что три коммита и оба файла появились на GitHub.

## Первый коммит — пример команд

```bash
git status
git add lab02/NOTES.md
git diff --staged
git commit -m "Document local Git states"
git log --oneline -3
```

Сначала создайте и сохраните NOTES.md в редакторе. Не копируйте команды без соответствующих изменений. Для второго и третьего коммита выбирайте относящиеся к ним файлы и сообщения.

## Отправка

```bash
git push origin main
```

В этой инструкции используется ветка main. Для вашей другой ветки подставьте её имя. Если запросили вход, выполните предусмотренную GitHub авторизацию; имя автора коммитов не заменяет вход.

## Что сдавать

Ссылка на свой fork и полный SHA последнего коммита (`git rev-parse HEAD`). В отчёте укажите SHA двух предыдущих коммитов; финальный SHA укажите в сообщении сдачи, чтобы избежать ссылки коммита на самого себя.

## Критерии — 10 баллов

| Критерий | Баллы |
|---|---:|
| Три собственных последовательных и осмысленных коммита | 3 |
| NOTES.md: верное объяснение Git, GitHub и трёх состояний | 2 |
| Разбор status, diff и diff --staged в отчёте | 2 |
| Изменения опубликованы в собственном fork | 1 |
| Ответы на защите и воспроизводимая история действий | 2 |

Коммиты преподавателя и пустые коммиты не заменяют выполнение задания. Количество пройденных Python-тестов для этой практики не применяется: автоматический анализ истории ещё не реализован.
