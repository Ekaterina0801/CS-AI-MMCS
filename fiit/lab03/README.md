## Задача

Датчик передаёт подряд несколько записей. Запись — либо число (показание), либо слово
`error`, если датчик не смог измерить величину.

### Ввод

| Строка | Что в ней |
|---|---|
| 1 | порог — число |
| 2 | `n` — количество записей, целое |
| 3 … `n`+2 | показание (число) или слово `error` |

Хотя бы одно показание в списке всегда корректно.

### Вывод — пять строк в этом порядке

| № | Что вывести |
|:---:|---|
| 1 | сколько записей пришло всего |
| 2 | сколько среди них ошибок |
| 3 | сколько превышений: показание **строго больше** порога |
| 4 | максимальное показание — **с одним знаком после точки** |
| 5 | среднее показание — **с одним знаком после точки** |

Максимум и среднее считаются только по корректным показаниям: `error` в них не участвует.

### Пример

```
Ввод:        Вывод:
25           5
5            1
24.5         2
30.1         30.1
error        25.2
19
27.3
```

Пришло 5 записей, одна испорчена, порог превысили `30.1` и `27.3`, самое большое показание —
`30.1`, среднее четырёх корректных — `25.2`.

### Ещё пример

```
Ввод:        Вывод:
10           3
3            0
10           1
10           11.0
11           10.3
```

Показание, **равное** порогу, превышением не считается: сравнение строгое.
Среднее — `(10 + 10 + 11) / 3 = 10.333…`, печатается как `10.3`.

> **Оформление свободное:** подписи вроде `Ошибок: 1` и приглашения в `input()` допустимы —
> проверяются значения и их порядок. Но число знаков после точки у максимума и среднего
> должно быть как в примере: `30.1`, а не `30` или `30.10`.

## Подсказки по разбору

- Строку сравнивайте со словом `error` **до** преобразования в число: `float("error")`
  завершит программу ошибкой.
- Среднее считайте накопительно: заводите сумму и количество корректных показаний,
  а в конце делите одно на другое.
- Максимум ищите так же: заводите переменную и обновляйте её, когда очередное показание
  больше. Нулём её начинать нельзя — показания бывают отрицательными.
- Пропустить испорченную запись внутри цикла помогает `continue`.

## Проверьте себя до сдачи

| Случай | Что должно получиться |
|---|---|
| все записи корректны | ошибок 0, среднее по всем показаниям |
| корректное показание одно | максимум и среднее равны ему |
| все показания отрицательные | максимум — наибольшее из них, а не 0 |
| показание равно порогу | превышением не считается |

## Как сдать

```bash
git add lab03/sensor.py
git commit -m "Count sensor errors and threshold hits"
git push
git rev-parse HEAD
```

В сервисе проверки → **Отправить решение** → «Лабораторная 03». Укажите ссылку на свой
репозиторий, в поле ветки — `main` или полный SHA из команды выше.

Затем **продублируйте сдачу в [Moodle](../../README.md#moodle)**: ссылку на репозиторий и тот же SHA.

## Что проверяется автоматически

| Что смотрит сервис | Что от вас нужно |
|---|---|
| автотесты | 12 тестов: 6 открытых и 6 скрытых; проверяются значения и их порядок |
| точность | у максимума и среднего — один знак после точки |
| публикация | не меньше трёх собственных коммитов в вашем репозитории |

Скрытые тесты показывают только «пройден / не пройден»: так решение не получится подогнать
под конкретные числа.
