## Зачем функции

В третьей работе вся программа была одним куском: читала ввод, считала, печатала. Пока задача
маленькая, это терпимо. Как только расчётов становится несколько, кусок приходится копировать —
и ошибку потом исправлять во всех копиях.

Функция — это **названный кусок работы**: у неё есть вход (параметры) и выход (возвращаемое
значение). Один расчёт описан один раз, вызывается сколько угодно раз.

```python
def average(scores):
    return sum(scores) / len(scores)

print(average([7, 9, 8]))          # 8.0
print(average([3, 4]))             # 3.5
```

## Объявление, параметры, вызов

```python
def winner(names, scores):     # def, имя, параметры в скобках, двоеточие
    best = 0                   # тело — со сдвигом в четыре пробела
    ...
    return names[best]         # что функция отдаёт наружу
```

| Термин | Что это |
|---|---|
| **параметр** | имя в скобках при объявлении: `names`, `scores` |
| **аргумент** | значение, переданное при вызове: `winner(группа, баллы)` |
| **вызов** | `winner(names, scores)` — выполнить функцию и получить результат |

Имена параметров — внутреннее дело функции. Снаружи списки могут называться иначе:
функция работает с тем, что ей передали.

## return и print — разные вещи

Это главное место, где путаются.

| | `return` | `print` |
|---|---|---|
| Что делает | отдаёт значение вызывающему коду | печатает текст на экран |
| Можно ли сохранить результат | да: `best = winner(...)` | нет, печать никуда не возвращается |
| Прекращает ли работу функции | да, сразу | нет |

```python
def average_bad(scores):
    print(sum(scores) / len(scores))      # напечатает, но вернёт None

mean = average_bad([7, 9])                # mean = None — дальше работать не с чем
```

Функция без `return` возвращает `None`. Проверка сравнит `None` с ожидаемым значением
и не засчитает тест, даже если на экране всё выглядело правильно.

`return` ещё и **прерывает** функцию: код после него не выполнится.

## Списки: индексация и перебор

Список хранит значения по порядку. Нумерация с нуля.

```python
names = ["Аня", "Боря", "Вика"]
names[0]        # "Аня"
names[2]        # "Вика"
names[-1]       # "Вика" — последний
len(names)      # 3 — количество, а не индекс
```

`names[len(names)]` — всегда `IndexError`: последний индекс на единицу меньше длины.

Три способа пройти список:

| Способ | Когда удобен |
|---|---|
| `for name in names:` | нужны только значения |
| `for i in range(len(names)):` | нужен номер — например, чтобы взять `scores[i]` |
| `for name, score in zip(names, scores):` | нужны значения сразу из двух списков |

### Параллельные списки

Два списка одинаковой длины, где элементы с одним номером относятся к одному объекту:

```
индекс:   0       1       2
names:  "Аня"  "Боря"  "Вика"
scores:  7.0     9.0     8.0
```

Поэтому поиск победителя удобно вести **по номеру**: `scores[i]` сравниваем, `names[i]` отдаём.

```python
best = 0
for i in range(1, len(scores)):
    if scores[i] > scores[best]:
        best = i
```

Сравнение строгое (`>`): равный результат не вытесняет уже найденного, и при равенстве
побеждает тот, кто раньше.

## Сортировка

`sorted` возвращает **новый** список, `list.sort()` меняет существующий:

```python
sorted([3, 1, 2])          # [1, 2, 3], исходный список цел
values.sort()              # исходный список изменён, возвращает None
```

Если исходные данные менять нельзя — только `sorted`.

Параметр `key` говорит, по какому значению сравнивать:

```python
order = sorted(range(len(names)), key=lambda i: -scores[i])   # номера по убыванию балла
names_sorted = [names[i] for i in order]
```

Сортировка в Python **устойчивая**: элементы с одинаковым ключом сохраняют исходный
взаимный порядок. Поэтому участники с равными баллами в рейтинге идут так же, как в протоколе.

## Функция вызывает функцию

```python
def above_average(names, scores):
    mean = average(scores)          # свой же расчёт, описанный один раз
    return [name for name, score in zip(names, scores) if score > mean]
```

Так среднее считается в одном месте. Если формула изменится, править придётся одну функцию,
а не три.

## Пограничные случаи

| Случай | Что ломается без проверки |
|---|---|
| пустой список | `sum(scores) / len(scores)` — деление на ноль |
| все значения равны | при нестрогом `>=` победителем окажется последний, а не первый |
| отрицательные значения | «лучший» заведён нулём — ни один результат его не превысит |
| один элемент | цикл `range(1, len(scores))` не выполнится ни разу — и это правильно |
