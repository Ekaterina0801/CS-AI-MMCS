## Данные

Две таблицы — `events.csv` и короткая `events-small.csv` — лежат рядом с этим условием,
а в сервисе проверки их можно скачать прямо на странице практики, в блоке
**«Файлы к практике»**.

Скопируйте обе в папку `lab05` своего репозитория и **не изменяйте** — по ним проверяется работа.

```
дата,тип,минуты
2026-03-01,запуск,1.5
2026-03-01,ошибка,0.4
```

CSV — обычный текстовый файл. Первая строка — **заголовок**: названия колонок. Каждая следующая
строка — запись, поля разделены запятыми. Никакой магии в формате нет, поэтому **модуль `csv`
в этой работе использовать нельзя**: разбираем строки сами, чтобы понять устройство.

Встречаются испорченные строки — с другим числом полей. Их пропускают.

## Что реализовать в `tablestats.py`

| Функция | Что делает |
|---|---|
| `read_rows(lines)` | строки CSV → список словарей `{колонка: значение}`; первая непустая строка — заголовок |
| `count_types(rows)` | сколько записей каждого типа |
| `total_minutes(rows, kind)` | суммарные минуты записей одного типа, округлить до десятых |
| `to_csv(counts)` | сводка текстом CSV: заголовок `тип,количество`, строки по алфавиту |

```python
read_rows(["дата,тип,минуты", "2026-03-01,запуск,1.5"])
# [{"дата": "2026-03-01", "тип": "запуск", "минуты": "1.5"}]

count_types(rows)                 # {"запуск": 4, "ошибка": 4}
total_minutes(rows, "ошибка")     # 2.5
to_csv({"ошибка": 4})             # "тип,количество\nошибка,4\n"
```

Правила разбора:

- пустые строки пропускаются;
- пробелы вокруг значений отбрасываются;
- строка, где полей не столько же, сколько в заголовке, пропускается;
- в `total_minutes` нечисловое значение пропускается, запятая считается десятичной точкой;
- если записей такого типа нет, `total_minutes` возвращает `0.0`.

`lines` — **последовательность строк**: список или сам открытый файл. Перебирайте её обычным
`for`, не обращаясь по индексу.

## Что делает `main.py`

Читает имя таблицы из первой строки ввода, открывает её и печатает три числа:

1. сколько записей прочитано;
2. сколько различных типов;
3. суммарные минуты записей типа `ошибка`.

Затем записывает сводку в `summary.csv` рядом с собой, в кодировке UTF-8.

```
Ввод:            Вывод:
events.csv       14
                 4
                 2.5
```

Запустить и проверить:

```bash
cd lab05
echo events.csv | python main.py
cat summary.csv
```

Готовый `summary.csv` закоммитьте вместе с кодом: он часть сдачи.

## Чтение и запись файлов

```python
with open(path, encoding="utf-8") as table:
    rows = read_rows(table)

with open("summary.csv", "w", encoding="utf-8") as out:
    out.write(to_csv(counts))
```

`with` закрывает файл сам, даже если программа упадёт. `encoding="utf-8"` обязателен: без него
берётся кодировка системы, и на другом компьютере русские названия типов прочитаются неверно.

Режимы открытия: `"r"` — чтение (по умолчанию), `"w"` — запись с нуля, прежнее содержимое
стирается, `"a"` — дописывание в конец.

## Проверьте себя до сдачи

| Случай | Что должно получиться |
|---|---|
| строка с лишним полем | пропущена, программа работает дальше |
| пробелы вокруг значений | отброшены: `" запуск "` и `"запуск"` — один тип |
| минуты записаны как `1,5` | посчитаны как 1.5 |
| типа нет в таблице | `total_minutes` вернула `0.0` |
| `main.py` на `events-small.csv` | числа другие — имя файла берётся из ввода, а не зашито |

## Как сдать

Работа принимается **только ссылкой на репозиторий** — файлы прикреплять не нужно и нельзя.

1. Положите `tablestats.py`, `main.py`, обе таблицы и полученный `summary.csv` в папку `lab05`
   репозитория `cs-practice`.
2. Отправьте работу на GitHub — не меньше четырёх коммитов:

```bash
git add lab05
git commit -m "Add CSV parsing functions"
git push
git rev-parse HEAD
```

3. Откройте репозиторий в браузере и убедитесь, что все пять файлов там есть.
4. В сервисе проверки → **Отправить решение** → «Лабораторная 05». Укажите ссылку
   на репозиторий, в поле ветки — `main` или полный SHA.

Затем **продублируйте сдачу в [Moodle](../../README.md#moodle)**: там тоже прикрепляется
**ссылка и полный SHA**, а не файлы.
