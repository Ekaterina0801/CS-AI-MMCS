## Зачем массив, если есть список

Список хранит ссылки на произвольные объекты: в нём могут лежать число, строка и другой список.
Массив NumPy хранит **числа одного типа подряд одним блоком памяти**. Отсюда два следствия:

| | Список | Массив NumPy |
|---|---|---|
| типы элементов | любые | один на весь массив |
| операция над всеми | цикл | одно выражение |
| скорость на больших данных | медленно | быстро |

```python
import numpy as np

values = [1, 2, 3]
doubled_list = [v * 2 for v in values]      # цикл

arr = np.array([1, 2, 3])
doubled = arr * 2                            # сразу ко всем элементам
```

Такое поведение называют **векторизацией**: вы описываете, что сделать с данными,
а не как обойти их по одному.

## Создание и тип

```python
np.array([1, 2, 3])                   # из списка
np.asarray(matrix, dtype="float64")   # без лишнего копирования, с явным типом
np.zeros((2, 3))                      # таблица 2×3 из нулей
np.arange(6)                          # 0, 1, 2, 3, 4, 5
```

Тип задают явно. Если смешать числа и строки, NumPy приведёт всё к строкам,
и арифметика перестанет работать:

```python
np.array([1, "два"])        # dtype='<U21' — это строки!
np.asarray(data, dtype="float64")   # так надёжнее
```

## Форма

**Форма** (`shape`) — размеры по осям. У таблицы это `(строк, столбцов)`.

```python
arr = np.arange(6)
arr.shape            # (6,)   — один ряд из шести чисел
table = arr.reshape(2, 3)
table.shape          # (2, 3) — две строки по три
```

`reshape` не меняет сами числа и их порядок — только то, как они разложены.
Поэтому количество элементов должно совпадать: шесть чисел раскладываются в 2×3 или 3×2,
но не в 2×4. Иначе NumPy возбудит ошибку — в работе этот случай обрабатывается заранее.

`-1` означает «посчитай сам»: `arr.reshape(-1, 3)` — три столбца, строк сколько получится.

## Индексация и срезы

```python
table[0]          # первая строка
table[0, 2]       # элемент: строка 0, столбец 2
table[:, 1]       # весь столбец 1
table[1:, :2]     # со второй строки, первые два столбца
```

Через запятую указывают оси: сначала строки, потом столбцы. Срез `start:stop` не включает
`stop`, как и у списков.

> **Срез — это вид на те же данные, а не копия.** Изменив срез, вы измените исходный массив.
> Нужна независимая копия — `table[1:, :2].copy()`.

### Выбрать произвольные строки и столбцы

Обычная индексация двумя списками берёт **пары** координат:

```python
table[[0, 2], [1, 2]]          # элементы (0,1) и (2,2) — два числа
```

Чтобы взять пересечение — строки 0 и 2 целиком по столбцам 1 и 2 — нужна сетка индексов:

```python
table[np.ix_([0, 2], [1, 2])]  # таблица 2×2
```

Это ровно то, что делает `block` в задании.

## Операции вдоль осей

```python
table.mean(axis=0)    # среднее по каждому столбцу
table.mean(axis=1)    # среднее по каждой строке
table.max() - table.min()
```

`axis=0` — «схлопнуть строки», результат по столбцам. `axis=1` — наоборот. Это самое частое
место для ошибки: если результат получился не той длины, почти всегда перепутана ось.

| Выражение | Что считает |
|---|---|
| `arr.mean(axis=0)` | среднее каждого столбца |
| `arr.sum(axis=1)` | сумму каждой строки |
| `arr[:, 2].max()` | наибольшее в третьем столбце |
| `arr.argmax(axis=1)` | номер наибольшего в каждой строке |

## Обратно в обычные типы

Результат NumPy — это `np.float64` и `np.ndarray`, а не `float` и `list`. Для сравнения
с ожидаемым значением и для записи в JSON их переводят:

```python
float(arr.mean())                       # обычное число
[float(v) for v in arr]                 # обычный список
[[float(v) for v in row] for row in arr]  # таблица
```

## Точность дробных чисел

Дробные числа хранятся приближённо: `0.1 + 0.2` даёт `0.30000000000000004`. Поэтому результаты
округляют: `round(float(value), 6)`. Шести знаков хватает для учебных данных и достаточно,
чтобы сравнение не зависело от порядка операций.
