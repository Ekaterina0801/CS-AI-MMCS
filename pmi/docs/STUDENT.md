## Что понадобится

| Что | Для чего | Когда |
|---|---|---|
| **Python 3.11+** | запускать решения | с первой лабораторной |
| редактор кода | писать программы | с первой лабораторной |
| **Git** | вести историю изменений | со второй лабораторной |
| **аккаунт GitHub** | хранить и сдавать работы | со второй лабораторной |

Проверьте Python: `python --version`. Если команда не находится, попробуйте `python3` или, в Windows, `py`,
и используйте её во всех примерах.

## Первая лабораторная — без Git

1. Создайте на компьютере папку `lab01`.
2. Прочитайте [условие](../lab01/README.md) и [теорию](../lab01/THEORY.md).
3. Напишите семь программ `task01.py` … `task07.py`.
4. Сдайте файлы в сервисе проверки — отдельными файлами или одним ZIP-архивом.
5. Продублируйте те же файлы в [Moodle](../../README.md#moodle).

Можно скачать заготовки прямо с GitHub: **Code → Download ZIP** на главной странице репозитория,
папка `pmi/lab01`.

## Со второй лабораторной — свой репозиторий

1. На GitHub нажмите **+ → New repository**. Имя — `cs-practice`, видимость — **Public**.
   Галочки README, `.gitignore` и license **не ставьте**: репозиторий должен быть пустым.
2. Скопируйте HTTPS-адрес нового репозитория и подставьте его вместо `YOUR_REPO_URL`:

```bash
git clone YOUR_REPO_URL cs-practice
cd cs-practice
git remote -v
```

`origin` должен указывать на ваш репозиторий. **Не выполняйте `git init`** — `clone` уже создал репозиторий.
В этом же репозитории ведите и все следующие лабораторные: каждую — в своей папке `labNN` в корне.

3. Задайте автора коммитов своими данными:

```bash
git config user.name "Имя Фамилия"
git config user.email "student@example.com"
```

Вход в GitHub и подпись автора коммитов — **разные** настройки. Не сохраняйте токены в файлах проекта.

## Когда появляются новые задания

Условия публикуются в [репозитории курса](https://github.com/Ekaterina0801/CS-AI-MMCS) — читайте их там.
Ваш репозиторий с курсом не связан, синхронизировать ничего не нужно: создайте в нём папку новой
лабораторной и работайте как обычно.

Если `push` отклонён или появился конфликт — остановитесь и напишите преподавателю. Не применяйте
`push --force` и команды удаления изменений.
