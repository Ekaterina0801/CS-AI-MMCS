## Подготовка репозитория

Нужны Git, учётная запись GitHub и выполненная первая работа.

1. Откройте [репозиторий курса](https://github.com/Ekaterina0801/CS-AI-MMCS) и нажмите **Fork** —
   GitHub создаст вашу копию.
2. В своём fork нажмите **Code → HTTPS** и скопируйте адрес.
3. Клонируйте fork, подставив адрес вместо `YOUR_FORK_URL`:

```bash
git clone YOUR_FORK_URL cs-practice
cd cs-practice
git status
git remote -v
git log --oneline -5
```

Сам текст `YOUR_FORK_URL` не является рабочим адресом. `origin` должен указывать на **ваш** fork.
Если локальная копия уже есть, откройте её папку вместо повторного `clone`.

> ⚠️ **Не выполняйте `git init` внутри клонированного репозитория** — получится вложенная история,
> не связанная с вашим fork, и сервис не сможет отличить ваши коммиты.

Все дальнейшие команды выполняются **из корня репозитория**. Создайте в корне папку `lab02` — в ней
будете вести `NOTES.md` и `REPORT.md`. Путь `lab02` отсчитывается от корня и не зависит от папки
первой работы.

## Автор коммитов

```bash
git config user.name "Ваше имя"
git config user.email "ВАШ_EMAIL"
```

Команды задают автора коммитов в текущем репозитории — они **не выполняют вход** в GitHub.
Для `push` используйте настроенный способ авторизации GitHub.

## Акцент для ПМИ

В `NOTES.md` дополнительно объясните, какое состояние файла сохраняет коммит и почему сохранение файла не равно коммиту.

## Три собственных изменения

### 1. Первый коммит: локальные состояния

Создайте `lab02/NOTES.md`. Своими словами определите **рабочую папку**, **индекс** и **коммит**.
Добавьте пояснение для своего направления. Сохраните файл, затем:

```bash
git status
git add lab02/NOTES.md
git diff --staged
git commit -m "Describe local Git states"
git log --oneline -3
```

### 2. Второй коммит: Git и GitHub

Дополните `NOTES.md` различием Git и GitHub. **До `add`** посмотрите изменения рабочей копии,
**после `add`** — подготовленные изменения. Объясните, какие состояния сравнивают две команды `diff`.

```bash
git diff
git add lab02/NOTES.md
git diff --staged
git commit -m "Explain Git and GitHub"
```

### 3. Третий коммит: отчёт и отправка

Заполните `lab02/REPORT.md` по требованиям ниже и сохраните отдельным коммитом:

```bash
git add lab02/REPORT.md
git commit -m "Add lab02 report"
git branch --show-current
git push origin main
```

В примере используется ветка `main`. Если `git branch --show-current` показал другое имя,
подставьте его. Откройте свой fork в браузере и проверьте, что файлы и **все три** ваших коммита
появились на GitHub.

Каждый коммит должен содержать реальное изменение. Унаследованные коммиты преподавателя и пустые
коммиты не заменяют три ваших шага.

## Содержание REPORT.md

<details>
<summary><b>Структура отчёта</b> — разделы, которые проверяет сервис</summary>

```markdown
# Отчёт · Лабораторная 02

## Автор
ФИО, группа, направление, ссылка на свой fork.

## Коммиты
Полные SHA первых двух собственных коммитов и что изменилось в каждом.

## Состояния файла
Что показывал git status до add, после add и после commit — и почему.
Разбор git diff и git diff --staged для второго изменения.

## Публикация
Какие файлы и коммиты видны на GitHub.
```

</details>

* ФИО, группа, направление и ссылка на свой fork.
* Полные SHA первых двух собственных коммитов и описание каждого изменения.
* Состояние файла до `add`, после `add` и после `commit`: наблюдаемый `status` и объяснение различий.
* Разбор `git diff` и `git diff --staged` для второго изменения.
* Подтверждение публикации: какие файлы и коммиты видны на GitHub.

Последний SHA в отчёт **не вписывайте**: изменение отчёта создаст новое состояние, и SHA перестанет
совпадать с тем, что вы сдаёте.

## Как сдать

```bash
git rev-parse HEAD
```

В сервисе проверки → **Отправить решение** → «Лабораторная 02». Укажите ссылку на свой fork, а в
поле ветки — `main` или полный SHA из команды выше: сервис проверит ровно этот коммит.

Затем **продублируйте сдачу в [Moodle](../../README.md#moodle)**: ссылку на свой fork и тот же полный SHA.

## Что проверяется автоматически

Сервис читает историю вашего репозитория и отличает ваши коммиты от унаследованных при форке.

| Что смотрит сервис | Что от вас нужно |
|---|---|
| собственные коммиты | не меньше трёх, каждый — реальное изменение |
| `NOTES.md` | раскрыты рабочая папка, индекс, коммит и различие Git и GitHub |
| `REPORT.md` | разобраны `git status`, `git diff` и `git diff --staged` |
| публикация | коммиты есть в вашем fork на GitHub |
