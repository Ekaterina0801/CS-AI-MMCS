Воркшоп: проведите маленький проект через несколько состояний и научитесь возвращать его
в любое из них. Сравнение версий, поиск изменений, восстановление файлов, безопасная отмена
коммита, теги и ветка для эксперимента.

## Что вы сдаёте

Работа ведётся в папке `lab03` вашего репозитория `cs-practice` — того самого, что вы завели
во второй лабораторной. Два файла:

| Файл | Что это |
|---|---|
| `calc.py` | проект, который меняется от коммита к коммиту |
| `NOTES.md` | журнал воркшопа: какую команду выполнили, что она показала и зачем нужна |

`NOTES.md` — не отчёт «для галочки». Это ваши рабочие записи: по ним вы будете отвечать
на защите, а сервис проверит, что разобраны все шесть тем воркшопа.

```bash
cd cs-practice
git switch main
git pull
mkdir lab03
```

## 1. Три состояния проекта

Создайте `lab03/calc.py` — программу, которая читает два числа и печатает результат.
Развивайте её **тремя отдельными коммитами**:

| Коммит | Что добавляете |
|---|---|
| 1 | чтение двух чисел и сложение |
| 2 | вычитание |
| 3 | умножение |

```bash
git add lab03/calc.py
git commit -m "Add sum calculation"
```

Три коммита нужны не ради числа: дальше вы будете сравнивать эти состояния между собой
и возвращаться к ним.

## 2. Сравнение версий и поиск изменений

Посмотрите, что и когда менялось:

```bash
git log --oneline --stat
git diff HEAD~2 HEAD -- lab03/calc.py
git show HEAD~1
```

`HEAD` — текущий коммит, `HEAD~1` — предыдущий, `HEAD~2` — на два раньше.

Теперь найдите, **в каком коммите появилась** конкретная строка:

```bash
git log -S"input" --oneline -- lab03/calc.py
git blame lab03/calc.py
```

В `NOTES.md` запишите, чем `git diff` отличается от `git show` и `git log`, и что именно
нашли `log -S` и `blame`. Сохраните заметки отдельным коммитом.

## 3. Восстановление файла

Испортите `calc.py`: удалите в нём пару строк и сохраните файл, **не коммитьте**. Посмотрите,
что видит Git, и верните файл к последнему коммиту:

```bash
git status
git diff
git restore lab03/calc.py
```

Теперь достаньте **старую версию** файла, посмотрите её и верните текущую обратно:

```bash
git restore --source=HEAD~2 lab03/calc.py
git diff
git restore lab03/calc.py
```

> ⚠️ `git restore` затирает несохранённые правки в файле безвозвратно: Git о них не знал.
> Перед восстановлением всегда смотрите `git status`.

Запишите в `NOTES.md`, чем `git restore <файл>` отличается от `git restore --source=...`.
Коммит.

## 4. Ошибочный коммит и его отмена

Добавьте в `calc.py` деление — **без** проверки деления на ноль — и закоммитьте эту ошибку.
Это сделано специально: так у вас появится, что отменять.

```bash
git add lab03/calc.py
git commit -m "Add division"
git log --oneline
git revert HEAD
git log --oneline
```

`revert` не стирает коммит, а создаёт новый, отменяющий его изменения. Посмотрите, что
в истории теперь **два** коммита: ошибка и её отмена.

В `NOTES.md` объясните, чем это отличается от `git reset --hard` и почему в опубликованной
истории безопаснее `revert`. Коммит.

## 5. Тег рабочей версии

Отметьте состояние, в котором проект работает, и отправьте тег на GitHub:

```bash
git tag -a v1.0 -m "Рабочая версия калькулятора"
git tag
git show v1.0
git push origin main
git push origin v1.0
```

Обычный `git push` отправляет коммиты, но **не теги** — тег отправляется отдельно.

Запишите в `NOTES.md`, чем тег отличается от ветки.

## 6. Эксперимент в ветке

Рискованную правку делают не в `main`. Верните деление, но уже с проверкой нуля, — в ветке:

```bash
git switch -c experiment
# правка calc.py: деление с проверкой на ноль
git commit -am "Add safe division"
git switch main
git merge --no-ff experiment
git branch -d experiment
git push
```

Если бы эксперимент не удался, ветку можно было бы просто удалить — `main` осталась бы
нетронутой. Это и есть главная причина работать в ветке.

## Как сдать

```bash
git push
git push origin v1.0
git rev-parse HEAD
```

В сервисе проверки → **Отправить решение** → «Лабораторная 03». Укажите ссылку на свой
репозиторий, в поле ветки — `main` или полный SHA из команды выше.

Затем **продублируйте сдачу в [Moodle](../../README.md#moodle)**: ссылку на репозиторий и тот же SHA.

## Что проверяется автоматически

| Что смотрит сервис | Что от вас нужно |
|---|---|
| собственные коммиты | не меньше восьми, каждый — реальный шаг работы |
| сообщения коммитов | по сообщению понятно, что изменилось |
| отмена изменений | в истории есть коммит, созданный командой `git revert` |
| ветвление | ветка `experiment` слита в `main` коммитом слияния |
| тег | тег стоит на вашем коммите и отправлен на GitHub |
| `NOTES.md` | разобраны `diff`, `log`, `restore`, `revert`, тег и ветка |
