## Коммит как состояние проекта

Каждый коммит хранит **полный снимок** проекта, а не только изменённые строки. Поэтому любое
состояние можно восстановить целиком, а разницу между двумя состояниями Git вычисляет на ходу.

```
● ── ● ── ● ── ●   ← main (HEAD)
│    │    │    └ последний коммит
│    │    └ HEAD~1
│    └ HEAD~2
└ первый коммит
```

`HEAD` — указатель на текущий коммит. `HEAD~1` — его родитель, `HEAD~2` — на два шага назад.
Вместо `HEAD~N` можно писать сокращённый SHA из `git log --oneline`.

## Чем отличаются diff, show и log

| Команда | На какой вопрос отвечает |
|---|---|
| `git diff A B` | чем состояние B отличается от состояния A |
| `git show <коммит>` | что было в одном коммите: автор, сообщение и его изменения |
| `git log` | какие коммиты вообще были |

Полезные варианты:

| Команда | Что показывает |
|---|---|
| `git log --oneline` | по строке на коммит |
| `git log --stat` | какие файлы задел каждый коммит и на сколько строк |
| `git log -p` | историю вместе с изменениями каждого коммита |
| `git log --graph --all` | все ветки картинкой |
| `git diff -- <файл>` | изменения только в одном файле |

## Поиск изменений

Когда история длинная, вопрос звучит иначе: **где** изменилась нужная строка.

| Команда | Что делает |
|---|---|
| `git log -S"текст" -- <файл>` | находит коммиты, где число вхождений строки изменилось: там она появилась или исчезла |
| `git log --grep="текст"` | ищет по сообщениям коммитов |
| `git blame <файл>` | для каждой строки файла — коммит и автор, который её добавил |

`blame` — не поиск виноватого, а способ узнать, зачем строка появилась: по коммиту видно
сообщение и соседние изменения.

## Восстановление файлов

`git restore` берёт версию файла из истории и кладёт её в рабочую папку.

| Команда | Откуда берёт версию | Что затирает |
|---|---|---|
| `git restore <файл>` | из последнего коммита | несохранённые правки в этом файле |
| `git restore --source=HEAD~2 <файл>` | из указанного коммита | текущее содержимое файла |
| `git restore --staged <файл>` | ничего не берёт: убирает файл из индекса | подготовку к коммиту, правки остаются |

> ⚠️ Восстановление **не спрашивает подтверждения**. Правки, которых нет ни в индексе,
> ни в коммите, Git не хранит нигде, и вернуть их нельзя. Привычка простая:
> сначала `git status`, потом `restore`.

Версия из старого коммита, положенная в рабочую папку, — обычное изменение: её можно
закоммитить как новое состояние. История при этом не переписывается.

## Отмена коммита: revert и reset

| | `git revert <коммит>` | `git reset --hard <коммит>` |
|---|---|---|
| Что делает | создаёт новый коммит, отменяющий изменения | сдвигает ветку назад, коммиты после неё выпадают из истории |
| История | сохраняется целиком | переписывается |
| Опубликованные коммиты | безопасно | опасно: у других они уже скачаны |
| Когда применять | ошибка уже на GitHub | ошибка только у вас, локально |

После `revert` в истории **два** коммита: ошибочный и отменяющий. Это не беспорядок,
а честная запись: видно и ошибку, и исправление.

Отменить коммит слияния тоже можно, но Git должен знать, к какой линии возвращаться:
`git revert -m 1 <sha>`.

## Теги

**Тег** — постоянное имя для коммита. В отличие от ветки он не двигается: ветка
переезжает на каждый новый коммит, тег остаётся там, где поставлен.

| | Ветка | Тег |
|---|---|---|
| Двигается при коммите | да | нет |
| Зачем | вести работу | назвать готовую версию |

| Тип | Команда | Что внутри |
|---|---|---|
| Аннотированный | `git tag -a v1.0 -m "..."` | отдельный объект: автор, дата, сообщение |
| Лёгкий | `git tag v1.0` | просто имя коммита |

Для версий используют аннотированный. Отправляется тег отдельно: `git push origin v1.0`
или сразу все — `git push --tags`.

## Ветка для эксперимента

Ветка стоит дёшево: это имя и указатель на коммит. Поэтому рискованную правку делают в ветке,
а не в `main`.

```
                ● Add safe division        ← experiment
               ╱                  ╲
● ── ● ── ● ──●────────────────────● Merge  ← main
```

| Исход эксперимента | Что делаете |
|---|---|
| получилось | `git switch main`, затем `git merge --no-ff experiment` |
| не получилось | `git switch main`, затем `git branch -D experiment` — `main` не пострадала |

`--no-ff` сохраняет в истории след ветки: без него Git просто передвинет `main` вперёд.
