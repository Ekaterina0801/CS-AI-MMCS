## Что было

Метеостанция ведёт журнал наблюдений. Строка журнала — `город;температура;дата`:

```
Азов;24.5;2026-07-01
Таганрог;30;2026-07-01
Азов;25.5;2026-07-02
```

Разбирал его такой скрипт — всё в одном файле, без единой проверки:

```python
import sys

lines = sys.stdin.read().splitlines()
total = {}
count = {}
for line in lines:
    city, temp, date = line.split(";")
    total[city] = total.get(city, 0) + float(temp)
    count[city] = count.get(city, 0) + 1
best = ""
for city in total:
    if best == "" or total[city] / count[city] > total[best] / count[best]:
        best = city
print(len(lines))
print(0)
print(total[best] / count[best])
```

Что с ним не так:

| Проблема | Чем это кончается |
|---|---|
| пустая строка или лишняя `;` | `ValueError` при распаковке, программа обрывается |
| температура `н/д` | `ValueError` в `float`, обрывается |
| всё в одном файле | расчёт нельзя вызвать из другой программы или проверить тестом |
| пропущенные строки не считаются | в отчёте всегда `0` |

## Что нужно сделать

Разделите программу на **два файла**:

| Файл | Что внутри |
|---|---|
| `stats.py` | функции обработки. Ввода с клавиатуры и печати здесь нет |
| `main.py` | программа: читает журнал, вызывает функции из `stats.py`, печатает отчёт |

`main.py` импортирует функции из соседнего модуля:

```python
from stats import average_by_city, read_valid, warmest_city
```

## Что реализовать в `stats.py`

| Функция | Что делает |
|---|---|
| `parse_record(line)` | разбирает строку в словарь `{"city": ..., "temperature": ..., "date": ...}`; негодная строка → `ValueError` |
| `read_valid(lines)` | разбирает список строк, пропуская пустые и негодные; возвращает список словарей |
| `average_by_city(records)` | средняя температура по каждому городу, округлённая до десятых |
| `warmest_city(records)` | город с наибольшей средней температурой; при равенстве — первый по алфавиту |

```python
parse_record("Азов;24.5;2026-07-01")
# {"city": "Азов", "temperature": 24.5, "date": "2026-07-01"}

read_valid(["Азов;24.5;2026-07-01", "мусор", "Азов;25.5;2026-07-02"])
# [{"city": "Азов", ...}, {"city": "Азов", ...}]

average_by_city(records)   # {"Азов": 25.0, "Таганрог": 30.0}
warmest_city(records)      # "Таганрог"
```

Лишние пробелы вокруг полей отбрасывайте, запятую в числе (`-3,5`) считайте десятичной точкой.

## Проверка данных и ошибки

`parse_record` — единственное место, где разбирается строка, и единственное место, где
принимается решение, что строка негодная:

- полей не ровно три → `raise ValueError(...)`;
- город или дата пустые → `raise ValueError(...)`;
- температура не число → `float` сам возбудит `ValueError`; перехватите его и возбудите
  свой — с понятным сообщением.

`read_valid` вызывает `parse_record` в `try` / `except ValueError` и **пропускает** негодные
строки, а не роняет программу. Пустые строки пропускаются молча: они не считаются
ни корректными, ни испорченными.

Так ответственность разделена: одна функция решает, что строка плохая, другая — что с такой
строкой делать. Это и есть переработка, ради которой даётся задача: в другой программе ту же
`parse_record` можно использовать иначе — например, останавливаться на первой ошибке.

## Что печатает `main.py`

Три строки в этом порядке:

1. сколько записей разобрано;
2. сколько строк пропущено из-за ошибок;
3. средняя температура самого тёплого города — **с одним знаком после точки**.

```
Ввод:                      Вывод:
Азов;24.5;2026-07-01       3
мусор                      1
Азов;25.5;2026-07-02       30.0
Таганрог;30;2026-07-01
```

Журнал подаётся на вход программы и читается до конца:

```python
lines = sys.stdin.read().splitlines()
```

## Проверьте себя до сдачи

| Случай | Что должно получиться |
|---|---|
| строка с лишним полем | пропущена, программа работает дальше |
| пустая строка | не считается ни корректной, ни пропущенной |
| все строки испорчены | разобрано 0, пропущено столько, сколько непустых строк |
| два города с равной средней | самый тёплый — первый по алфавиту |

## Как сдать

Работа принимается **только ссылкой на репозиторий** — файлы прикреплять не нужно и нельзя.

1. Положите `stats.py` и `main.py` в папку `lab04` репозитория `cs-practice`.
2. Отправьте работу на GitHub — не меньше четырёх коммитов: разбиение на модули, проверки,

3. Откройте свой репозиторий в браузере и убедитесь, что оба файла там есть.
4. В сервисе проверки → **Отправить решение** → «Лабораторная 04». Укажите ссылку на свой

Затем **продублируйте сдачу в [Moodle](../../README.md#moodle)**: там тоже прикрепляется
**ссылка на репозиторий и полный SHA**, а не файлы.

> он читает то, что лежит на GitHub, а не то, что осталось на вашем компьютере.
