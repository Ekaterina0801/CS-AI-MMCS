## Почему скрипт «на одном дыхании» плох

Код из условия делает всё сразу: читает ввод, разбирает строки, считает средние и печатает.
Пока данные идеальны, он работает. Проблемы начинаются потом:

| Что хочется | Почему не выходит |
|---|---|
| проверить расчёт тестом | расчёт нельзя вызвать отдельно: он выполняется при запуске файла |
| использовать разбор строки в другой программе | он вплетён в цикл чтения |
| не падать на одной плохой строке | решение о плохой строке нигде не принимается явно |

Лечится это разделением: **что считать** отделяют от **откуда взять данные и куда вывести**.

## Модули

Модуль — обычный файл `.py`, из которого можно взять функции:

```python
# main.py
from stats import read_valid, average_by_city
```

Python ищет `stats.py` рядом с запускаемым файлом, поэтому оба файла лежат в одной папке.

| В модуль `stats.py` | В программу `main.py` |
|---|---|
| функции, которые считают и возвращают | чтение ввода |
| проверки корректности данных | вызовы функций |
| ничего не печатают | печать отчёта |

Правило простое: **функция возвращает, программа печатает**. Функция, которая печатает
вместо возврата, годится ровно для одной программы и не проверяется тестом.

> При импорте модуль выполняется целиком. Если в `stats.py` окажется `print` или `input`
> на верхнем уровне, они сработают при каждом импорте — в том числе у проверки.

## Коллекции под задачу

| Коллекция | Когда | Пример из работы |
|---|---|---|
| список | последовательность однотипного | записи журнала |
| словарь | доступ по ключу | `город → средняя температура` |
| множество | нужна уникальность | список городов без повторов |

Запись журнала удобно держать словарём: поля названы, а не пронумерованы.

```python
{"city": "Азов", "temperature": 24.5, "date": "2026-07-01"}
record["temperature"]        # понятнее, чем record[1]
```

Накопление по ключу — типовой приём:

```python
totals[city] = totals.get(city, 0.0) + temperature
counts[city] = counts.get(city, 0) + 1
```

`get(key, default)` возвращает значение по умолчанию, если ключа ещё нет, — и ветвление
«а если города ещё не было» не требуется.

## Исключения

Исключение — сообщение о том, что работу продолжить нельзя. Его **возбуждают** там,
где обнаружили проблему, и **перехватывают** там, где знают, что с ней делать.

```python
def parse_record(line):
    parts = [p.strip() for p in line.split(";")]
    if len(parts) != 3:
        raise ValueError(f"Нужно три поля через «;», получено {len(parts)}")
    ...
```

```python
def read_valid(lines):
    records = []
    for line in lines:
        if not line.strip():
            continue
        try:
            records.append(parse_record(line))
        except ValueError:
            continue          # эта программа плохие строки пропускает
    return records
```

Почему решения разнесены: `parse_record` отвечает только на вопрос «годится ли строка».
Что делать с негодной — пропустить, остановиться, записать в отчёт — решает тот, кто вызывает.
В другой программе та же функция пригодится с другим решением.

| Конструкция | Что делает |
|---|---|
| `raise ValueError("...")` | возбудить ошибку, прервав функцию |
| `try: ... except ValueError: ...` | перехватить ошибку этого типа и продолжить |
| `raise ... from None` | не тянуть в сообщение исходную ошибку |

> **Не пишите голый `except:`.** Он проглотит и опечатку в коде, и `KeyboardInterrupt`, —
> ошибка перестанет быть видна. Перехватывают конкретный тип: `except ValueError`.

Частые встроенные ошибки:

| Исключение | Когда возникает |
|---|---|
| `ValueError` | значение не того вида: `float("н/д")` |
| `KeyError` | нет ключа в словаре: `means["Азов"]` |
| `IndexError` | нет элемента по индексу: `parts[2]` при двух полях |
| `ZeroDivisionError` | деление на ноль: среднее от пустого списка |

## Организация программы

Порядок, по которому собирается `main.py`:

```
прочитать вход → получить корректные записи → посчитать → напечатать
 sys.stdin        read_valid(lines)           average_by_city   print
```

Каждый шаг — отдельный вызов. Такую программу легко менять: чтобы читать не с клавиатуры,
а из файла, меняется только первая строка; расчёты не трогаются вовсе.

## Генераторы (на будущее)

Когда данных много, список целиком в памяти не нужен — хватает перебирать по одному.
Это делают генераторы:

```python
def valid_records(lines):
    for line in lines:
        try:
            yield parse_record(line)      # отдаёт значение и ждёт следующего запроса
        except ValueError:
            continue
```

`yield` вместо `return`: функция возвращает не список, а объект, который выдаёт значения
по мере перебора. В этой работе достаточно списка, но приём пригодится, когда журнал
перестанет помещаться в память.
