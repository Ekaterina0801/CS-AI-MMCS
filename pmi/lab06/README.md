Короткая практика на пару: три маленькие функции о путях и размерах файлов.
Каждая — в две-пять строк.

| | |
|---|---|
| 📘 Теория | [THEORY.md](THEORY.md) |
| 🧾 Шпаргалка | [CHEATSHEET.md](CHEATSHEET.md) |
| 🖥 Лекция | [материалы лекций](../../materials/README.md) |

> ⚠️ **Работа принимается только ссылкой на репозиторий.** Файлы и ZIP-архив не принимаются.
> Решение, не отправленное на GitHub командой `git push`, сервис не увидит.

---

## Что реализовать

Все функции — в файле `solution.py`. Список путей даёт обход каталога (`pathlib`, `os.walk`);
сам обход уже сделан, функции получают готовый список строк. Настоящую файловую систему
трогать не нужно — так разбор путей проверяется тестами.

| Функция | Что возвращает |
|---|---|
| `count_by_extension(paths)` | словарь «расширение → сколько файлов»; в нижнем регистре, без точки |
| `deepest_path(paths)` | путь с наибольшей вложенностью; при равенстве — первый по алфавиту |
| `human_size(n_bytes)` | размер в удобных единицах: `1536` → `"1.5 КБ"` |

```python
paths = ["docs/report.PDF", "notes.txt", "docs/img/logo.png", "Makefile"]

count_by_extension(paths)    # {"pdf": 1, "txt": 1, "png": 1, "": 1}
deepest_path(paths)          # "docs/img/logo.png"

human_size(900)              # "900 Б"
human_size(1536)             # "1.5 КБ"
human_size(5 * 1024 * 1024)  # "5.0 МБ"
```

## Правила

- Расширение — то, что после **последней** точки в имени файла, в нижнем регистре.
  У файла без точки (`Makefile`) расширения нет: ключ `""`.
- Вложенность считается по числу разделителей `/` в пути.
- Единицы `human_size`: `Б`, `КБ`, `МБ`, `ГБ`, `ТБ` — каждая следующая в 1024 раза больше.
  Байты выводятся целым числом, остальные — с одним знаком после точки.
- `deepest_path([])` возвращает пустую строку.
- Функции **возвращают** результат, а не печатают его.
