CSV, JSON и YAML: что где хранят, как устроено внутри и почему форматы не взаимозаменяемы.

## Три формата и три задачи

| Формат | Сильная сторона | Слабая сторона |
|---|---|---|
| **CSV** | компактная однородная таблица, читается построчно | нет типов и вложенности, всё строки |
| **JSON** | вложенные структуры, типы сохраняются, читается машиной | многословен, комментариев нет |
| **YAML** | удобен человеку: комментарии, списки, меньше знаков | легко ошибиться отступом, разбор сложнее |

Отсюда обычное разделение ролей: данные — в CSV или JSON, **настройки — в YAML**.

## CSV: строки и запятые

```
id,город,цена
1,Азов,100
2,Шахты,200
```

Первая строка — заголовок. Разбор сводится к `split(",")` и сопоставлению с заголовком:

```python
header = [c.strip() for c in lines[0].split(",")]
row = dict(zip(header, [c.strip() for c in line.split(",")]))
```

**Чего в CSV нет:** типов (всё строки), вложенности, комментариев. Значение `100` придётся
превратить в число самому. В настоящем CSV значения с запятыми берут в кавычки — такой файл
разбирают модулем `csv`.

## JSON: типы и вложенность

```json
{
  "id": "1",
  "город": "Азов",
  "координаты": {"широта": 47.1, "долгота": 39.4},
  "теги": ["юг", "река"]
}
```

JSON различает строку `"100"` и число `100`, хранит словари и списки любой глубины.
Это формат обмена: его отдают и принимают почти все программы.

```python
import json

json.loads(text)                     # текст -> объекты Python
json.dumps(data, ensure_ascii=False, indent=2, sort_keys=True)
```

| Параметр | Зачем |
|---|---|
| `ensure_ascii=False` | кириллица остаётся буквами, а не `Аз...` |
| `indent=2` | отступы: файл читается человеком |
| `sort_keys=True` | одинаковые данные дают одинаковый текст |

Последнее важнее, чем кажется: без сортировки два одинаковых по смыслу файла отличаются
порядком ключей, и системы контроля версий показывают несуществующие изменения.

## YAML: формат для человека

```yaml
# отчёт за март
title: Отчёт за март
decimals: 1
active: true
columns:
  - город
  - цена
```

| Элемент | Что значит |
|---|---|
| `ключ: значение` | обычная пара |
| `#` | комментарий до конца строки |
| `ключ:` без значения | дальше идёт список |
| `- элемент` | элемент списка |

YAML **типизирован**: `1` — число, `true` — логическое значение, `Отчёт` — строка.
Поэтому при разборе значение пробуют привести к числу, затем к логическому типу,
и только потом оставляют строкой.

В работе разбирается учебное подмножество — без вложенности и многострочных значений.
Это сделано нарочно: пока формат разбираешь руками, видно, из чего он состоит.
В реальном коде берут `PyYAML` и `yaml.safe_load`.

> `safe_load`, а не `load`: полный YAML умеет создавать объекты Python, и загрузка чужого
> файла превращается в запуск чужого кода.

## Объединение данных

Таблица и справочник соединяются по общему ключу:

```python
addition = extra.get(str(row.get(key, "")), {})
combined = dict(addition)     # сначала справочник
combined.update(row)          # поверх — сама запись
```

Порядок здесь и есть правило разрешения конфликта: **данные записи важнее справочных**.
Если бы `update` шёл наоборот, справочник затирал бы то, что пришло из таблицы.

Записи без пары остаются как есть — иначе объединение незаметно теряло бы данные.
Это общее правило: операция над данными не должна молча уменьшать их количество.

## Проверка данных

Перед сохранением стоит убедиться, что данные пригодны: на месте ли обязательные поля,
числа ли там, где ожидаются числа. Удобный приём — множества:

```python
required = {"id", "город", "цена"}
missing = required - set(record)
if missing:
    raise ValueError(f"не хватает полей: {sorted(missing)}")
```
